## R2. Project generation and shape

- **Decision**: generate inside the Node container:

  ```
  ng new backoffice --directory src/web/backoffice --routing --style=scss --ssr=false
    --zoneless --test-runner=vitest --skip-git --package-manager=npm
  ```

  Then run `ng add @angular/material` and `ng add angular-eslint`.
  - Zoneless is the default from v21 (angular.dev/guide/zoneless). *Verify* that `app.config.ts` has no `provideZoneChangeDetection` and that `zone.js` is absent.
  - Standalone components are the default (`ng new --standalone` defaults to `true`).
  - The default test runner is Vitest with jsdom through `@angular/build:unit-test`.
- **Comments**: the CLI writes comments into generated files (`tsconfig*.json`, `styles.scss`, `app.config.ts`, sample specs). Principle IX applies to all of them, so every generated comment is removed and the sample spec replaced.
- **Folder**: `src/web/backoffice/` is self-contained. It has its own `package.json`, lockfile, `angular.json`, `Dockerfile`, `compose.yaml`, `nginx.conf` and `.dockerignore`.

## R3. Serving under `/backoffice/`

- **Decision**: build with `baseHref: "/backoffice/"` in the build target. That writes `<base href="/backoffice/">`, which angular.dev prefers over `--deploy-url`. Output goes to `dist/backoffice/browser/` and is copied to `/usr/share/nginx/html/backoffice/`.
- **nginx config** (`nginx.conf` → `/etc/nginx/conf.d/default.conf`):
  - `listen 8080`; `root /usr/share/nginx/html`.
  - `location /backoffice/ { try_files $uri $uri/ /backoffice/index.html; }`. Paths that are not files fall back to the host page, as angular.dev requires.
  - `location = /backoffice/index.html`: `Cache-Control: no-cache` (also reached by the fallback, an internal redirect).
  - `location ~ "^/backoffice/.+-[A-Z0-9]{8}\.(js|css)$"`: `Cache-Control: public, max-age=31536000, immutable`. Only hashed output files get this.
  - `location = /health { return 200; }` for the container health check.
  - Security headers on every answer:
    - `X-Content-Type-Options: nosniff`
    - `Referrer-Policy: same-origin`
    - `Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'`

    `'unsafe-inline'` for styles is needed for Angular's component styles. No external fonts or CDNs: Material uses the system font stack. No icon font: icons are inline SVG registered with `MatIconRegistry.addSvgIconLiteral`, or text buttons.
  - The caching and CSP values are our choice, because angular.dev gives no nginx example. They are tested in CI (R9).
- **Image facts** (nginx-unprivileged README): it listens on 8080 and has no `user` directive. The pid file and temp paths are under `/tmp`. Only `conf.d/default.conf` is replaced, so `nginx.conf` keeps those settings. The health check uses `wget`, *verify* it is present in the Alpine image (BusyBox).
- **Gateway**: the `backoffice-spa` cluster address moves to `http://backoffice-spa:8080` in `appsettings.json` and `src/gateway/compose.yaml` (FR-012).

## R4. The session module (`src/app/session/`)

- **`SessionService`**: the only owner of sign-in state, kept as a signal. The states are in data-model.md, Session state.
  - `load()` calls `GET /bff/backoffice/user`:
    - 200 → `signed-in`
    - 401 → `signed-out`
    - anything else or a network error → `unavailable`
  - `signIn()` calls `location.assign('/bff/backoffice/login?returnUrl=' + encodeURIComponent(path))`. The path is the current backoffice path and query, without `signin-error`.
  - `signOut()` calls `location.assign(user.logoutUrl)`.
  - The browser location is injected through a small `BROWSER_LOCATION` token, so tests never navigate.
- **Sign-in error**: read once at start from `location.search`, then removed with `history.replaceState`. Messages are in contracts/ui.md.
- **`apiInterceptor`** (functional, `provideHttpClient(withInterceptors([apiInterceptor]))`):
  - Only for URLs that start with `/api/`. It adds `X-Bff-App: backoffice` and nothing else, since cookies go automatically on same-origin requests.
  - 401 marks the session `signed-out` with the current path, then rethrows, so screens stop loading.
  - 503 with problem type `identity-unavailable` sets a `retryNeeded` signal and returns an observable that waits for the user's "Try again". It then re-sends the same request (FR-008).
  - Other answers pass through.
- **Shell**: `AppComponent` renders by state: a loading bar, `SignInComponent`, `UnavailableComponent`, or `ShellComponent` (toolbar, user menu, `<router-outlet>`, home placeholder). No route guard is needed, because nothing under the router renders until the state is `signed-in` (FR-001).
- **Size**: the module (service, interceptor, location token, error messages) is about 100–150 lines and is copied into the storefront in 017.

## R5. Development mode in Docker

- **Decision**: `deploy/compose.web-dev.yaml` is an extra compose file that `dev.ps1 -WebDev` adds with `-f`. It does two things:
  - Adds `backoffice-dev`: `NODE_IMAGE`, source bind-mounted at `/app`, an anonymous volume for `/app/node_modules`. Its command is:

    ```
    npm ci && npx ng serve --host 0.0.0.0 --port 4200 --serve-path /backoffice/
      --allowed-hosts backoffice-dev --poll 1000
    ```

  - Overrides the gateway's `ReverseProxy__Clusters__backoffice-spa__Destinations__main__Address` to `http://backoffice-dev:4200`.
- **Options**: `--allowed-hosts` passes through to Vite's host check (angular.dev/cli/serve). `--poll` is needed because file events don't cross a Windows bind mount.
- **Hot reload**: Vite's update socket goes through YARP, which proxies WebSockets. *Verify* that the update socket path is under `/backoffice/` and that a change shows within 5 seconds (SC-004). The gateway override uses the same merge as R7, which is verified.
- **Rejected**: `ng serve` on the host (breaks "everything in Docker"), and a separate dev port (cookies and callbacks are bound to `localhost:8080`).

## R6. Lint and unit tests

## R7. End-to-end tests (`tests/e2e/`)

- **Contents**: `package.json` (`@playwright/test` 1.65.1, lockfile), `playwright.config.ts`, `specs/backoffice-sign-in.spec.ts`, `compose.e2e.yaml`, and a runner `scripts/e2e.ps1`.
- **Config** (playwright.dev/docs/test-configuration):
  - `forbidOnly` in CI, `retries: 1` in CI
  - `trace: 'retain-on-failure'`, *verify* the value, with `'on-first-retry'` as the fallback
  - `reporter: [['list'], ['html', { open: 'never' }]]`
  - output to `tests/e2e/test-results`, which is git-ignored and uploaded by CI on failure
- **Stack**: `docker compose -p e2e-test -f deploy/compose.yaml -f tests/e2e/compose.e2e.yaml`, with profiles `infra,apps,e2e`. The override makes four changes:
  1. `ports: !reset []` on every service that publishes one (databases, RabbitMQ, gateway).
  2. `volumes: !reset []` plus `tmpfs` for the data and key paths: Postgres data, RabbitMQ data, `/keys` for Identity and the gateway. No named volume is used (principle VII).
  3. Adds `playwright` (profile `e2e`): `PLAYWRIGHT_IMAGE`, `network_mode: "service:gateway"`, `init: true`, `ipc: host`. The tests bind-mount at `/e2e` with an anonymous `node_modules`. The command is `npm ci && npx playwright test`.
  4. `BASE_URL=http://localhost:8080`.
- **Why the network setting**: sharing the gateway's network namespace means the browser reaches the gateway as `localhost:8080`. The origin then equals the dev `GATEWAY_ORIGIN`: Identity's issuer and redirect URIs match, and `Secure` cookies are accepted. Nothing is published on the host.
- **Root**: the image runs as root, which playwright.dev accepts for trusted test code.
- **Runner** (`scripts/e2e.ps1`): first `restore-feed.ps1 -Service identity`, because the Identity image build pulls BuildingBlocks from the feed. Then `up --build --detach --wait` for the stack, then `run --rm playwright`. In `finally`, it always runs `down -v --remove-orphans` and `check-test-cleanup.ps1 -Project e2e-test` (principle VII), and exits with the test's code.
- **CI**: `.github/workflows/e2e.yml`. Paths: `src/web/**`, `src/gateway/**`, `src/services/identity/**`, `tests/e2e/**`, `deploy/**`, the scripts and itself. It runs `scripts/e2e.ps1` and uploads `test-results` on failure. Two separate `if: always()` steps also run `docker compose -p e2e-test down -v --remove-orphans` and `check-test-cleanup.ps1 -Project e2e-test`, as principle VII requires, even if the runner itself was killed.
- **Credentials**: a variable in the override file is interpolated from the project environment, not from `dev.env`, which is attached only to the includes. So the `playwright` service gets `env_file: [../../deploy/dev.env]` (container environment, no interpolation) and reads `DEMO_ADMIN_EMAIL` and `DEMO_ADMIN_PASSWORD` from it.
- **Verified**: a second `-f` file does merge into services that came from `include:`. `docker compose -f deploy/compose.yaml -f <override> config` showed an added environment variable and the gateway's port removed by `ports: !reset []`. This holds for R5 and R7.

## R11. Implementation findings

- **Generated project.** `ng new` in Angular 22.3 is zoneless: no `zone.js`, no zone change detection. It writes TypeScript `~6.0.2`, Vitest 5 and jsdom, plus `.vscode`, `README.md` and a project `.gitignore`. The editor folder, readme and project `.gitignore` were removed; the root `.gitignore` covers the build output. Comments came out of `tsconfig*.json`, `.editorconfig`, `eslint.config.js` (`// @ts-check`), `styles.scss` and `app.html`.
- **`ng add @angular/material` adds Google Fonts** (Roboto and Material Symbols) to `index.html`. They were removed because of the CSP and the no-CDN rule. The theme now uses `system-ui` for both font families, and the shell needs no icon font.
- **Critical CSS inlining breaks the CSP.** The production build inlines critical CSS and loads the stylesheet with an inline `onload` handler, which `default-src 'self'` blocks: the page stays unstyled. Unit tests can't see this; the real-browser check found it. Fix: `optimization.styles.inlineCritical: false` in the production configuration. The backoffice CI asserts that the host page has no `onload=`.
- **nginx-unprivileged and IPv6.** `listen 8080` binds IPv4 only, while `localhost` inside the Alpine container resolves to `::1`, so the `wget` health check was refused. Fix: also `listen [::]:8080`.
- **nginx `add_header` inheritance.** A location that sets its own `add_header` drops the server-level ones. The security headers live in `security-headers.conf`, which is included in the server block and in every location that adds `Cache-Control`.
- **Interpolation with `include`.** Variables in an extra `-f` file (`compose.web-dev.yaml`, `compose.e2e.yaml`) are interpolated from the project environment, not from the includes' `env_file`. Both scripts therefore pass `--env-file deploy/versions.env`, and the Playwright service reads credentials through its own `env_file`.
- **Paths in extra compose files** resolve against the first file's folder (`deploy/`), hence `../tests/e2e` and `dev.env` in `tests/e2e/compose.e2e.yaml`.
- **`tmpfs` permissions.** The Identity and gateway containers run as non-root, so their `/keys` are `tmpfs` with `mode: 01777`.
- **Hot reload through the gateway** works. Vite's socket connects to `ws://localhost:8080/backoffice/?token=…` through YARP. A text change appeared about 1.3 seconds after saving, with `--poll 1000` on the Windows bind mount. The dev server's `<base>` tag is self-closing (`/>`), so the smoke check matches only `<base href="/backoffice/"`.
- **Identity's sign-out confirmation.** Identity's end-session page (012) asks "Sign out?" even when the gateway sends a valid `id_token_hint`. So sign-out takes one extra click, and the end-to-end test clicks through it. Skipping the prompt for a valid hint from the same client is a possible Identity change for the owner to decide.
- **Silent sign-in.** A browser that still has Identity's `identity.session` cookie gets a new backoffice session without seeing the login page. That is expected single sign-on, but browser checks must start from cleared cookies.
- **Image-pin check.** Playwright tags carry a `v` prefix (`v1.65.1-noble`). The tag rule now accepts an optional `v`, and it requires a patch version for `node`, `nginx-unprivileged` and `playwright`.
- **Return path.** `SessionService.signIn()` builds the return path from the browser location at click time. The signed-out state therefore carries no stored path. data-model.md is updated to match.
- **Safety check.** A command running `rm` inside a container shell was refused. For temporary `node_modules`, mount an anonymous volume instead of deleting.
- **The `<base>` tag's form varies.** The CI build wrote `<base href="/backoffice/"/>` (self-closing), while the image built locally had `<base href="/backoffice/">`, and the dev server writes `/>` too. All checks match only `<base href="/backoffice/"`. The first suspect, `pipefail` with `grep -q`, was ruled out: the GitHub step runs plain `bash -e`, and the check still failed with the answers read into variables.
- **Playwright** accepted `trace: 'retain-on-failure'`. A deliberately failing run wrote `test-results/.../trace.zip`, tore the stack down and exited 1.
