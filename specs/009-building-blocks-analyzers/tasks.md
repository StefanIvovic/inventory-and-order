## Phase 4: User Story 2 - Saving inside a handler is an error (Priority: P1)

- [X] T006 [P] [US2] Write `SaveChangesInHandlerAnalyzerTests.cs` for spec US2 scenarios 1–5 and the data-model.md "Handler method" table:
  - **positive**: `CommandHandler<Db>` subclass calling `Db.SaveChangesAsync`; a static `XHandler.Handle` calling `db.SaveChanges()`; `Consume` on an `XConsumer`; a `[WolverineHandler]` type with a `Handles` method; saving inside a lambda and inside a local function within `Handle`
  - **positive (I1)**: a type implementing `Wolverine.IWolverineHandler` with a `Handle` method that saves
  - **negative (G1)**: a Wolverine-generated-style handler (an `// <auto-generated/>` header, a class deriving from Wolverine's runtime handler base, a `HandleAsync` method calling `SaveChangesAsync`) gives no diagnostic, so Static code generation in feature 011 can never break a service build
  - **negative**: a seeder class; a private helper method on a handler class; a `SaveChangesAsync` method on a non-DbContext type inside `Handle`; `Handle` on `OrderValidator` (not a handler name)
- [X] T007 [US2] Implement `SaveChangesInHandlerAnalyzer.cs` (research.md R4). Then make T006 pass
